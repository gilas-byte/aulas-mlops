# 📚 Aula 02 - Data Warehouse com DuckDB (OLTP → OLAP) 🤖

> 🇬🇧 **English** below · 🇧🇷 **Português** [mais abaixo](#-aula-02---data-warehouse-com-duckdb-oltp--olap-pt-br-)

## 🤖 What is this class about?

This class simulates a real **Data Warehouse pipeline**: it starts from an operational database (OLTP) and transforms it into an analytical Star Schema (OLAP) using DuckDB, then exports everything to Excel.

`Basically it shows how raw transactional data becomes ready-to-analyze data.`

## 📂 Files

- `modelagem.py` → creates the OLTP tables, builds the Star Schema and exports it to Excel.
- `requirements.txt` → the libs needed (duckdb, pandas, openpyxl...).
- `meu_data_warehouse.duckdb` → the DuckDB database file generated by the script.
- `data_warehouse_exportado.xlsx` → the final Excel file, with one sheet per table.

## ⚙️ Some technical things explained

- **OLTP (Online Transaction Processing):** the operational database, normalized in 3FN (3rd normal form), made for everyday reads/writes. Here it's `oltp_clientes`, `oltp_produtos`, `oltp_pedidos` and `oltp_itens_pedido`.
- **OLAP (Online Analytical Processing):** the analytical model, made for reports and queries over lots of data, not for daily transactions.
- **Star Schema (Kimball model):** one central fact table (`fato_vendas`, with the numbers/metrics) surrounded by dimension tables (`dim_cliente`, `dim_produto`, `dim_tempo`, with the descriptive attributes).
- **SK vs NK (Surrogate Key vs Natural Key):** the `sk_*` columns are new IDs created just for the warehouse (via `ROW_NUMBER()`), while `nk_*` keeps the original ID from the OLTP database.
- **DuckDB:** an embedded analytical database (like SQLite, but built for analytics), used here to run all the SQL without needing a server.

## ▶️ How to run

```
pip install -r requirements.txt
python modelagem.py
```

**After running, open `data_warehouse_exportado.xlsx` to see the Star Schema separated in sheets!**

# 📚 Aula 02 - Data Warehouse com DuckDB (OLTP → OLAP) (PT-BR) 🤖

## 🤖 Sobre o que é essa aula?

Essa aula simula um pipeline real de **Data Warehouse**: parte de um banco de dados operacional (OLTP) e transforma em um Star Schema analítico (OLAP) usando DuckDB, depois exporta tudo para Excel.

`Basicamente mostra como dado transacional bruto vira dado pronto pra análise.`

## 📂 Arquivos

- `modelagem.py` → cria as tabelas OLTP, monta o Star Schema e exporta pra Excel.
- `requirements.txt` → as libs necessárias (duckdb, pandas, openpyxl...).
- `meu_data_warehouse.duckdb` → o arquivo do banco DuckDB gerado pelo script.
- `data_warehouse_exportado.xlsx` → o Excel final, com uma aba por tabela.

## ⚙️ Algumas coisas técnicas explicadas

- **OLTP (Online Transaction Processing):** o banco operacional, normalizado em 3FN (3ª forma normal), feito pra leituras/escritas do dia a dia. Aqui são `oltp_clientes`, `oltp_produtos`, `oltp_pedidos` e `oltp_itens_pedido`.
- **OLAP (Online Analytical Processing):** o modelo analítico, feito pra relatórios e consultas em cima de muito dado, não pra transação do dia a dia.
- **Star Schema (modelo de Kimball):** uma tabela fato central (`fato_vendas`, com os números/métricas) cercada de tabelas dimensão (`dim_cliente`, `dim_produto`, `dim_tempo`, com os atributos descritivos).
- **SK vs NK (Surrogate Key vs Natural Key):** as colunas `sk_*` são IDs novos criados só pro data warehouse (via `ROW_NUMBER()`), enquanto `nk_*` guarda o ID original do banco OLTP.
- **DuckDB:** um banco de dados analítico embutido (tipo o SQLite, mas feito pra análise), usado aqui pra rodar todo o SQL sem precisar de servidor.

## ▶️ Como rodar

```
pip install -r requirements.txt
python modelagem.py
```

**Depois de rodar, abre o `data_warehouse_exportado.xlsx` pra ver o Star Schema separado em abas!**
